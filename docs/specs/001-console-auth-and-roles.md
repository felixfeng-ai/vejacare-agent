# 001 后台角色分离与鉴权

> 状态：**待确认**（2026-09-29 起草）
> 确认后才动代码。本文写的是"要做什么、为什么这么做"，实现细节以代码为准。

---

## 1. 背景与问题

三件事凑在一起，指向同一个缺口：**这个项目没有"谁在看"的概念**。

**1.1 后台接口完全裸奔。**
`/api/escalations`（工单队列、工单详情、以客服身份回复、结单）和
`/api/metrics/satisfaction`（满意度看板）没有任何鉴权：没有登录、没有令牌、
没有角色。任何知道地址的人都能读走全部工单——工单详情里带着用户对话原文——
并且能以"人工客服"的身份往任意会话里发消息。后端代码里找不到一处鉴权依赖，
`grep Authorization backend/app/` 是空的。

**1.2 前端把后台和用户端堆在同一页。**
前端是单页 `App.tsx`，没有路由。"数据看板"是页头的按钮，点开是一个抽屉。
于是**用户端页面上就摆着管理者的看板入口**。我在 2026-09-29 又照着同样的模式加了
一个"人工工单"抽屉，把这个问题放大了一倍：客服的工作台出现在了用户眼前。

**1.3 转人工缺客服侧的界面。**
用户说"转人工"后，横幅写着"人工回复后即可继续对话"，但真人客服没有任何地方
能看到这张工单、更没法回复。后端其实早就准备好了（队列、详情含 AI 完整上下文、
回复接口、回复后唤醒挂起的图让 AI 收尾），缺的只是一个界面。

**根因**：1.1 是缺鉴权，1.2 是缺路由与角色视图，1.3 是缺客服侧界面。
三者是同一件事的三面——**没有角色划分，就没有"后台"这个概念**。

---

## 2. 目标与非目标

### 目标

- 用户端只剩聊天与会话历史，页面上不出现任何后台入口
- 客服有工单工作台，管理者有看板，二者按角色可见
- 后台接口需凭证访问；未配置凭证时**拒绝服务而不是放行**
- 用户端聊天链路行为不变（现有 62 条后端测试 + 接口契约校验全绿）

### 非目标（本次不做，避免范围膨胀）

- 完整账号体系（用户表、密码哈希、找回密码、多用户管理）
- 审计日志与操作留痕（令牌里带署名是缓解，不是审计）
- 会话归属校验（见 §8 已知缺口，本次只记录不解决）

---

## 3. 角色与权限矩阵

| 能力 | 访客 | 用户端 | 客服 | 管理者 |
|------|:----:|:------:|:----:|:------:|
| 聊天、历史会话、满意度评价 | — | ✓ | ✓ | ✓ |
| 工单队列 / 详情 / 回复 / 结单 | — | — | ✓ | ✓ |
| 满意度看板 | — | — | — | ✓ |

**建议默认**：口令分两套（客服口令、管理口令），管理口令可访问客服的全部功能。
理由：权限矩阵要立得住，就不能一套口令走天下——否则客服令牌能看经营看板，
矩阵里那一行"管理者"就只是摆设。

---

## 4. 规格（验收标准）

- **AC1** 用户端页面（`/chat`）不存在"数据看板""人工工单"入口
- **AC2** 不带令牌调 `/api/escalations`、`/api/metrics/satisfaction` → `401`，
  且响应仍是统一信封（`success:false` + `error.code`）
- **AC3** 口令正确 → 返回令牌，令牌内含角色与过期时间
- **AC4** 客服令牌调工单接口 → 通过；调看板接口 → `403`
- **AC5** 令牌过期或被篡改 → `401`，前端清掉令牌并跳登录页
- **AC6** 后端未配置口令 → 后台接口一律 `503` 说明"后台未配置访问口令"，
  **绝不因为"没配"就放行**
- **AC7** 用户端的聊天、会话列表、历史、满意度提交不受影响

## 5. 技术方案

### 5.1 后端：口令换签名令牌

**新增配置**（`app/config.py`，四项）：

| 配置项 | 说明 |
|--------|------|
| `console_agent_password` | 客服口令 |
| `console_admin_password` | 管理口令 |
| `console_token_secret` | 令牌签名密钥 |
| `console_token_ttl_minutes` | 令牌有效期，默认 720（12 小时） |

**令牌格式**：`base64url(payload) + "." + hmac_sha256_hex(secret, base64url(payload))`，
payload 为 `{"role": "agent"|"admin", "name": "客服小美", "exp": <unix 秒>}`。

用标准库 `hmac` / `hashlib` / `base64` / `json` 实现，**不引第三方鉴权库**。
这个规模用 JWT 库属于杀鸡用牛刀，而手写这 30 行的过程恰好能讲清"签名令牌到底
在防什么"——防的是篡改，不是防窥探（payload 是明文 base64，谁都能解）。

**新增文件**：

- `app/security.py`：`require_role(*roles)` 依赖项。解析 `Authorization: Bearer`，
  校验签名（`hmac.compare_digest`，定时安全）与过期，命中则注入身份，否则 `401`。
- `app/api/console.py`：
  - `POST /api/console/login` —— 请求 `{password}`，响应 `{token, role, name, expires_at}`
  - `GET /api/console/me` —— 拿令牌换身份，用于前端刷新后恢复登录态

**保护范围**：

| 路由 | 归属 |
|------|------|
| `/api/escalations/**` | 客服（`require_role("agent", "admin")`） |
| `/api/metrics/satisfaction` | 管理者（`require_role("admin")`） |
| `/api/console/**` | 登录接口公开，`/me` 需登录 |
| `/api/chat`、`/api/sessions`、`/api/feedback`、`/api/health` | 保持公开（用户端） |

`/api/health` 保持公开：它只吐布尔型的"配没配 key"，不含密钥本身，
而部署自检脚本依赖它做存活判断。

**口令比较**用 `hmac.compare_digest`；登录失败加一个进程内的简单计数限流
（同一 IP 连续失败 5 次锁 60 秒），避免口令被在线穷举。

### 5.2 前端：加路由，按角色分视图

引 `react-router-dom` v6 作为唯一新依赖（gzip 约 10 kB）。

| 路由 | 页面 | 守卫 |
|------|------|------|
| `/` | 重定向到 `/chat` | — |
| `/chat` | 现在的 `App.tsx` 聊天页 | — |
| `/login` | 登录页（口令 → 令牌） | — |
| `/desk` | 客服工单台 | `RequireRole("agent", "admin")` |
| `/admin` | 满意度看板 | `RequireRole("admin")` |

- 令牌存 `localStorage`（键 `veyacare.console_token`）；`request()` 在带令牌时
  自动附加 `Authorization` 头
- 收到 `401` → 清令牌、跳 `/login`；收到 `403` → 页面内提示"当前角色无权访问"
- **用户端页头摘掉"数据看板"按钮**，客服/管理端页头放"返回用户端"与"退出登录"
- 已写的 `AgentDesk.tsx` 逻辑整体迁移到 `/desk`：队列、上下文、回复、结单都复用，
  只把"抽屉"外壳换成整页布局（抽屉是为了塞进用户页面才有的形状，路由页不需要）
- `MetricsPanel.tsx` 同理迁到 `/admin`

`vite.config.ts` 与 nginx **不需要改**：前端路由已由
`try_files $uri $uri/ /index.html` 兜住，直接刷新 `/desk` 不会 404。

### 5.3 契约变更

`docs/API.md` 新增第 6 节：登录接口、令牌传递方式、受保护接口清单、
`401` / `403` / `503` 三个错误码的语义。前端类型同步加进 `types.ts`。

## 6. 部署影响（这里有个坑）

**坑：生产的 `backend/.env` 不会被更新。**
`deploy/cicd-deploy.sh` 第 40-48 行的逻辑是"`.env` 不存在就从 `.env.example` 拷贝，
已存在则备份保留"。所以新增的 `CONSOLE_*` 四项**不会**随本次部署出现在服务器上，
后台接口会按 AC6 一律返回 503——功能上线了却登录不上。

**处理办法**：在部署脚本里加一步"补齐缺失的后台配置"——
检测 `.env` 里有没有 `CONSOLE_TOKEN_SECRET`，没有就**生成随机口令与密钥并追加**，
同时把生成的口令打到部署日志里（只打一次，之后从服务器 `.env` 里读）。
不把默认口令写进 `.env.example`：模板默认值必须是生产安全的，
给一个"admin/123456"的默认值等于给所有人留后门——这条原则 `.env.example` 里
`DEBUG=false` 的注释已经写过一次了。

`package-lock.json` 必须随 `react-router-dom` 一起提交：CI 与部署用的是 `npm ci`，
lock 与 `package.json` 不一致会直接失败。

## 8. 已知缺口（本次不解决，但要记在案）

**用户端接口没有归属校验**：`/api/sessions` 列出全部会话，
`/api/sessions/{id}/messages` 按 id 取任意会话的完整消息。
也就是说，**即使做完了后台鉴权，任何一个用户仍能读到别人的会话**。
这个缺口比后台裸奔更大，但它属于"用户身份"体系（需要会话令牌与归属绑定），
与本次"后台角色"是两件事。建议单独立项（002），本次仅在 `docs/API.md`
和 README 的"已知限制"里写明，不假装它不存在。

## 10. 风险与取舍

- **令牌存 localStorage**：XSS 可被读走。取舍是演示项目不引 httpOnly cookie
  所需的 CSRF 防护与跨域配置；写进文档，并说明真要上生产应该怎么改。
- **共享口令而非个人账号**：无法追责到具体某个人。回复时记客服署名是缓解手段，
  不是审计。真要做审计需要 §2 非目标里的账号体系。
- **限流是进程内的**：多进程部署会失效。本项目单进程 uvicorn，够用。
